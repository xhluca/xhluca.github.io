The actual fix

Muse speaks a dialect OpenRouter doesn’t.

Muse exposes a base URL, but its shipped OpenRouter provider is disabled. A direct key fails before the first token. The adapter resolves the three protocol mismatches without modifying Meta’s binary.

  1. 01

    Visible model picker

    Every live OpenRouter meta/muse* record is translated into a visible Muse catalog row, so Glimmer and Spark can be selected normally.

  2. 02

    Stream normalization

    Missing Responses API sequence numbers are added while the stream remains incremental.

  3. 03

    Credential handoff

    Your OpenRouter key stays outside Muse’s Meta login store and is supplied only to OpenRouter.

Secure by default

A small bridge, not another harness.

Private

The key is stored in a user-only credential file. Authorization headers, prompts, and responses are never logged.

Selectable

Choose the default during install, reopen the chooser with muse-openrouter select, or select per run with muse --model meta/muse-….

Portable

A dependency-free Python wheel supports Linux and macOS. The installer uses PyPI with a checksum-pinned fallback.

One command

Bring the key. Keep Muse.

$ curl -LsSf https://xhluca.github.io/muse-code-openrouter/install.sh | sh

The installer prompts for the key without echoing it, then shows a numbered model chooser. Run muse-openrouter select later to refresh and change the default. For Contributor models, OpenRouter warns: “Your prompts and outputs may be used to improve Meta's products.”
